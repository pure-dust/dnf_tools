# DNF 工具箱（排班工具）

基于 **Tauri v2 + Vue 3 + Vite + Less + TypeScript** 的桌面团本排班工具：统一管理成员与角色，按模板（人数 + 每队伤害/奶量门槛）自动生成排班，支持多班次、替补区、拖拽微调、历史与导出。

## 功能模块

- **排班模板**：维护模板（参与人数上限 + 每个队伍的伤害门槛/奶量门槛），队伍按门槛自动配色。
- **创建排班**：选模板 → 填时间 → 勾选参与角色 → 自动拆班/组队 → 拖拽微调 → 保存。
- **成员管理**：成员/角色增删改、批量导入（粘贴或 .json）、批量导出 JSON。
- **历史排班**：同一次排班（多“场”/多班）合并展示；支持总览、查看/导出、编辑（覆盖保存）、删除。
- **桌面端**：主题明暗切换、无边框窗口控制；数据存于应用数据目录，可导出图片/JSON。

# 排班规则与优先级（自动生成）

## 一、生成流程分两步

1. **拆班 `splitRounds(items, cap)`**：把勾选的全部角色分到 N 个“班次”，每班人数上限 = 模板人数上限（如 12 人模板即每班 ≤ 12）。
2. **逐班组队 `assignByLimits(teams, pool)`**：把每班的角色按该班各队门槛，塞进“每队 ≤ 4 人”的队伍；剩的人进入替补区（跨班合并为一个替补栏）。

## 二、具体规则

### 拆班阶段
- 输出按分数降序、辅助按分数降序，再交错成队列：**每 3 个输出插 1 个辅助**（尽量让每班能凑出 1辅 + 3出的队形）。
- 逐角色放进“最早可入”的班：从第 0 班起找第一个「未满、且**不含该成员其它角色**」的班。
- 前面的班先满，满了才开新班。
- 硬约束：每班 ≤ 每班人数上限；**同一成员的不同角色绝不在同一班**。

### 组队阶段（就近补齐）
- 队伍按**伤害门槛降序**逐个处理（门槛最高 = “红队”先拿人，依次红 → 黄 → 绿 → 蓝；同门槛保持原顺序）。
- 每队填人顺序：
  1. 先放 **1 个辅助**（满足奶量门槛 `healLimit` 的最高辅助；无人达标则取最高辅助）；
  2. 再用**输出**补到 4 人（满足伤害门槛 `damageLimit` 的最高者优先；无人达标则取“低于门槛但最高”——**就近补位**）；
  3. 若输出不够仍想满队，允许再补辅助。
- 人不够时队伍停在“不满 4 人”（偏队），不硬凑；某班人数超过队伍总容量才产生替补（每班 ≤ 模板人数，替补通常为 0）。

## 三、规则优先级（从高到低）

| 级别 | 规则 |
| --- | --- |
| P0 硬约束 | ① 同成员不同角色不能同班；② 每班 ≤ 每班人数上限；③ 每队 ≤ 4 人 |
| P1 分班 | **优先把前面的班填满（班数尽量少）**；同人尽量相邻仅为软偏好——不增加班数、不牺牲前班满员时才贴近 |
| P2 取人顺序 | 队伍按门槛高 → 低取人（红队优先拿最强） |
| P3 队内组成 | 理想 1辅 + 3出：先保 1 辅助，再补输出；缺输出才用辅助补位 |
| P4 选人标准 | 能达标 > 高分：同门槛下取“满足门槛的最高分”；整班无人达标时取“低于门槛但最高”（就近补位） |
| P5 补足策略 | 尽量凑满 4 人（就近补位优先于留空）；彻底无人可用才留不满队/停队 |

> 简记：**满员 / 填满前班 ＞ 同人连排**；**红队优先 ＞ 补满每队 ＞ 守住门槛 ＞ 门槛内取高分 ＞ 就近补位**。

## 四、展示与手动调整

- **队伍配色**：按伤害门槛降序给红 → 黄 → 绿 → 蓝（最多 4 队，超过循环），与门槛排名一致。
- **拖拽调整**：队内排序 / 同班跨队交换（满员时与目标队末位交换）；拖到右侧替补 = 移出该班；从替补拖回某班需满足「该队 ≤ 4 人」与「同成员不可同班」。
- **按本班各队门槛重新分配**：先收回该班被手动拖入替补的角色，再按该班当前门槛重新走 P2–P5。
- **编辑历史（整组）**：跳转到创建页载入原数据（模板、时间、各“场”队伍与参与勾选），保存为**覆盖原记录**（复用原场次 id/时间/groupId），不会新增历史。
- **门槛单位**：输出门槛与评分为“伤害”口径，辅助为“奶量”口径，`0` = 不限。

## 五、常见疑问

- **为什么红队偶尔收到“不能进红队”的角色？** 仅当该班内达标输出不足红队所需 C 位时，算法按“就近补位”放入低于门槛但最高的角色；只要有达标者，红队一定优先拿达标且最高的（不存在浪费）。
- **为什么有人角色很多时会拆出很多班、后面的班人少？** 班数下界 = `max(⌈总角色/每班⌉, 单成员最多角色数)`（同一成员不同角色不能同班所致）；大号成员的后半段角色必然落在较后班，且“先填满前面班”会令后面班偏少——这是接受“满员优先”后的必然结果。

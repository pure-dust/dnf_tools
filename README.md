# DNF 工具箱（排班工具）

基于 **Tauri v2 + Vue 3 + Vite + Less + TypeScript** 的桌面团本排班工具：统一管理成员与角色，按模板（人数 + 每队伤害/奶量门槛）自动生成排班，支持多班次、替补区、拖拽微调、历史与导出。

## 功能模块

- **排班模板**：维护模板（参与人数上限 + 每个队伍的伤害门槛/奶量门槛 + **最少输出/最少辅助人数**），队伍按门槛自动配色。
- **创建排班**：选模板 → 填时间 → 勾选参与角色 → 自动拆班/组队 → 拖拽微调 → 保存。
- **成员管理**：成员/角色增删改、批量导入（粘贴或 .json）、批量导出 JSON。
- **历史排班**：同一次排班（多“场”/多班）合并展示；支持总览、查看/导出、编辑（覆盖保存）、删除。
- **桌面端**：主题明暗切换、无边框窗口控制；数据存于应用数据目录，可导出图片/JSON。

# 排班规则与优先级（自动生成）

## 一、生成流程分两步

1. **拆班 `splitRounds(items, cap)`**：**先按模板每班上限定班数**（N = ⌈总角色 / cap⌉，如 78 号 ÷ 12 ≈ 7 班，班数不因成员/奶等规则增加）；随后做规则内填充（同人每班至多 1 号等），**放不进这些班的角色进入替补区**。
2. **逐班组队 `assignByLimits(teams, pool)`**：把每个班内已分配的角色按各队门槛，塞进“每队 ≤ 4 人”的队伍；队内容纳不下的人进入替补区（跨班合并为一个替补栏）。

## 二、具体规则

### 拆班阶段（先定班数 → 再按规则填充）
- **班次 = ⌈总角色 / 模板每班上限⌉**：计算班数时不考虑成员/奶等规则限制。
- **填充（按班，辅助先行 + 满员优先）**：每个班先配“该班可组满编队数个辅助”（≈ max(1, ⌊每班可坐/4⌋)：12 人班放 3 奶、8 人班放 2 奶、不足 4 人班放 1 奶，各奶来自不同成员；同人每班 1 号），再用输出把班补满；辅助不足时后面的班才缺奶（宁缺）。每班最多可坐 = min(模板每班上限, 参与成员数)（成员不足模板人数时装不满）。
- 已有班都放不下时：若未达计划班数则开新班；否则该角色**进入替补区**（不再增加班数）。
- 硬约束：每班 ≤ 模板每班上限；**同一成员的不同角色绝不在同一班**。
- 示例：6 名成员、78 号、12 人模板 → 计划 7 班；因每班最多 6 人（成员限制）7 班最多坐 42 人，多余角色进替补。

### 组队阶段（先辅助、后输出，两阶段）
- 每个队伍可设置 **最少输出人数 `minDps`** 与 **最少辅助人数 `minSup`**（默认 0 / 1）；队伍按**伤害门槛降序**处理（红队先拿，依次红 → 黄 → 绿 → 蓝）。
- **分两个阶段取人**：
  1. **辅助先行**：红队 → 黄队 → …，先把各队需要的辅助（minSup，以 minSup 为上限不超编）补齐；辅助耗尽或各队配额满足即停；
  2. **再排输出**：规则同辅助，红队 → 黄队 → …，先满足各队最少输出（minDps），再把每队补到 4 人（仅输出）。
- 取人满足门槛者优先（同满足取最高分），无人满足则**就近补位**；**只按定位（输出/辅助）选人，不按细分职业去重**。
- **宁缺不开碎队**：第一队（红队，门槛最高）尽力凑满 4 人，允许不满员；**非首队若最终凑不满一整队（输出不足只拿到辅助）会整队退回替补**，避免“黄/绿单挂 1 人碎队”。

## 三、规则优先级（从高到低）

| 级别 | 规则 |
| --- | --- |
| P0 硬约束 | ① 同成员不同角色不能同班；② 每班 ≤ 每班人数上限；③ 每队 ≤ 4 人 |
| P1 分班 | **班数 = ⌈总角色/模板每班上限⌉（先定班数，不因规则增加）**；填充时每班 ≤ min(上限, 成员数)；放不下的角色进替补 |
| P2 取人顺序 | 队伍按门槛高 → 低取人（红队优先拿最强） |
| P3 队内组成 | **两阶段**：先红→黄→…补各队辅助(minSup，不超编)；再红→黄→…保 minDps 并把每队补满 4 人（仅输出） |
| P4 选人标准 | 能达标 > 高分：同门槛下取“满足门槛的最高分”；整班无人达标时取“低于门槛但最高”（就近补位） |
| P5 宁缺 | 非首队最终凑不满一整队 → 整队退回替补（不开碎队）；首队允许不满员 |

> 简记：**固定班数 ＞ 每班按可组队数配辅助 ＞ 先各队辅助、后各队输出 ＞ 红队优先 ＞ 守门槛 ＞ 就近补位 ＞ 宁缺不开碎队**。

## 四、展示与手动调整

- **队伍配色**：按伤害门槛降序给红 → 黄 → 绿 → 蓝（最多 4 队，超过循环），与门槛排名一致。
- **拖拽调整**：队内排序 / 同班跨队交换（满员时与目标队末位交换）；拖到右侧替补 = 移出该班；从替补拖回某班需满足「该队 ≤ 4 人」与「同成员不可同班」。
- **按本班各队门槛重新分配**：先收回该班被手动拖入替补的角色，再按该班当前门槛重新走 P2–P5。
- **编辑历史（整组）**：跳转到创建页载入原数据（模板、时间、各“场”队伍与参与勾选），保存为**覆盖原记录**（复用原场次 id/时间/groupId），不会新增历史。
- **门槛单位**：输出门槛与评分为“伤害”口径，辅助为“奶量”口径，`0` = 不限。

## 五、常见疑问

- **为什么红队偶尔收到“不能进红队”的角色？** 仅当该班内达标输出不足红队所需 C 位时，算法按“就近补位”放入低于门槛但最高的角色；只要有达标者，红队一定优先拿达标且最高的（不存在浪费）。
- **为什么有人角色很多、替补却很多？** 班数先按 `⌈总角色/每班上限⌉` 定死（不再因“同人不同班/每班奶”等规则增加）；而每班最多能坐的人数受“同人每班 1 号”限制（≤ 参与成员数），当角色远超班次容量时，装不下的角色就进入替补区，需要你手动/用“自动补位”或加更多班处理。
- **为什么只有少数成员时“红队整班收、黄/绿全空”？** 每班最多坐的人数 = 参与成员数（同人每班 1 号）；人少时每个班只有一支可组满的 4 人队，按“门槛最高者先拿满”只填红队，其余不足一整队者宁缺进替补（不单挂碎队）。
- **为什么有的班没奶 / 有的班 1 奶？** 每班每个成员至多 1 号，通常每班只含少量奶；具体队伍由 `assignByLimits` 按各队“辅助≥ minSup”配置分配，班内奶不足或超出都会体现为队伍该队缺奶或替补，不会超编。
